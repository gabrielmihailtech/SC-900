SC-900 - Part 1: Security, Compliance & Identity Concepts

Shared Responsibility Model

Responsibility for security is shared between the customer and the cloud provider.

On-Premises: Customer responsible for everything.
IaaS: Shared responsibility.
PaaS: More responsibility shifted to provider.
SaaS: Provider manages most infrastructure, customer remains responsible for data, identities and access.
Defense in Depth

Layered security approach designed to protect systems and data.

Common layers:

Physical Security
Identity & Access
Network Security
Applications
Data Protection
CIA Triad

Three core security objectives:

Confidentiality → protect information from unauthorized access.
Integrity → ensure information remains accurate and unmodified.
Availability → ensure systems and data remain accessible.
Zero Trust

Security model based on:

Verify Explicitly
Use Least Privilege
Assume Breach

Never trust, always verify.

Encryption vs Hashing
Encryption
Reversible process.
Protects data at rest and in transit.
Uses keys.
Hashing
One-way process.
Used for password storage.
Commonly combined with salting.
Governance, Risk & Compliance (GRC)
Governance

Policies and security direction of an organization.

Risk Management

Identify, assess and reduce risks.

Compliance

Meeting legal, regulatory and industry requirements.

Key Takeaways
Security responsibility changes between On-Prem, IaaS, PaaS and SaaS.
Defense in Depth uses multiple security layers.
CIA Triad is the foundation of information security.
Zero Trust = Never Trust, Always Verify.
Encryption protects data, hashing protects passwords.
GRC helps organizations manage security and compliance requirements.
